= vidocq-runtime-integration-tests
:description: Multi-extension integration tests.

[.lead]
`vidocq-runtime-integration-tests` is the module that exercises Vidocq Runtime in multi-extension scenarios. It verifies that the Chappe + Vauban + Champollion + Foy + Cassini + Mansart composition behaves correctly end-to-end, independently of the official TCKs.

[cols="1,3"]

|===

== Scope

* Full runtime boot, validation of phase ordering.
* REST + CDI + JDBC interaction in end-to-end cases (create, read, transaction, rollback).
* Shutdown behaviour — virtual thread drain, pool close, HTTP listener release.
* What `vidocq create` writes: `vidocq-runtime-it-create` (profile `it`, on every CI run) runs
  `mvn verify vidocq:jlink` on a created REST application — its first `@VidocqTest` test included, then the jlink
  image `vidocq build jlink` makes — and fails on any warning but the three javac ones documented as expected.
* Regressions tracked by bugs documented in `vidocq-runtime/BUG.md`, `vidocq-runtime/CHAPPE-BUGS.md`, `vidocq-runtime/VAUBAN-BUGS.md`.

== Run

From the root of the monorepo, with its wrapper: every integration test module, once the reactor is installed
(`./mvnw -ntp install -DskipTests`).

[source,bash]
----
./mvnw -ntp -pl vidocq-runtime/vidocq-runtime-integration-tests -amd test
----

For one module, or one test of it:

[source,bash]
----
./mvnw -ntp -pl vidocq-runtime/vidocq-runtime-integration-tests/vidocq-runtime-it-cassini-rest -am test
./mvnw -ntp -pl vidocq-runtime/vidocq-runtime-integration-tests/vidocq-runtime-it-cassini-rest -am test \
    -Dtest=RestExtensionTest -Dsurefire.failIfNoSpecifiedTests=false
----

== Difference from TCKs

* **TCKs** (Cassini, Foy, Champollion, Vauban) verify conformance to Jakarta specifications — run behind each component's `tck` Maven profile or through its `run-official-tck-*.sh` script.
* **Integration tests** verify the orchestration internal to Vidocq Runtime — boot, lifecycle, inter-extension interaction, AOT readiness.

The two are complementary and both required to release a version.

== TDD convention

Per the workspace philosophy, every new feature of the Vidocq Runtime engine arrives via a red test in this module before any production code. See the workspace root `CLAUDE.md` for the full rule.
