= What's new
:description: Everything that changed in this component since the {release-version} release.

[.lead]
New in the `{project-version}` development line — everything listed here landed **after the {release-version} release** and is not part of it. Every entry links to the section that documents it, and those sections carry the [.tag-new]#NEW# badge. Each brick of the suite keeps its own page of this kind; xref:home::whats-new.adoc[the ecosystem index] gathers them. When the next release train ships, this page is frozen with it and restarts empty on the dev line.

== Web server

* xref:modules/vidocq-runtime-extensions.adoc#declarative-mounts-shared[Static files, REST and servlets on one prefix] [.tag-new]#NEW# — several mounts may share a prefix of a listener, `/` for all three for instance (Vidocq/vidocq#802): each request goes to the first one that has something for it, static files first, then the REST resources, then the servlets, and the last one answers what none before it served. `vidocq.http.mount.<name>.order`, `vidocq.rest.order` and `vidocq.servlet.order` change the order; two mounts of one prefix used to fail the start. The `http` section of the startup report lists each shared prefix with its mounts in order.
* xref:modules/vidocq-runtime-extensions.adoc#declarative-mounts[A mount without its `.path` key fails the start] [.tag-new]#NEW# — `vidocq.http.mount.<name>.path` declares a mount, and the other keys of a mount without it were ignored silently: a mount written with a guessed key served nothing, and a `restful` one still turned off the automatic REST mount. The start now fails, naming the missing key and the keys it would have ignored.
* xref:modules/vidocq-runtime-extensions.adoc#declarative-mounts[Every key of the declarative mounts] [.tag-new]#NEW# — the reference gives the keys common to every mount and those of `static`, `restful` and `websocket`, how to serve a page next to a REST API, and why a folder of static files named like a Java package (`web/`) answers 404 while `static/` and `META-INF/resources/` need no `opens`.
