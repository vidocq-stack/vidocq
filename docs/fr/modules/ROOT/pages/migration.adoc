== Depuis Quarkus

Vidocq-MPS emprunte explicitement le pattern d'extensions Quarkus.

[cols="1,1,2"]
|===
| Quarkus | Vidocq-MPS | Note

| `io.quarkus.deployment.annotations.BuildStep`
| `io.vidocq.mpserver.spi.BuildStep`
| API directement transposable

| Recorder Gizmo (ASM)
| Recorder Class-File API (JEP 484)
| Pas d'ASM — bytecode standard JDK

| ArC (CDI runtime)
| xref:vauban::index.adoc[Vauban]
| Build-time dans les deux cas

| RESTEasy Reactive
| xref:cassini::index.adoc[Cassini] sur xref:chappe::index.adoc[Chappe]
| Pas de Vert.x — virtual threads

| Hibernate Reactive / ORM
| xref:mansart::index.adoc[Mansart]
| JDBC + virtual threads, pas de Vert.x SQL Client

| Jackson
| xref:champollion::index.adoc[Champollion]
| Implémentation JSON-B 3.0 / JSON-P 2.1
|===

Les exemples `compare-to/` (à venir) du workspace illustreront la migration d'une extension simple.

== Depuis Helidon MP

* Helidon SE (Web) → xref:chappe::index.adoc[Chappe] + xref:cassini::index.adoc[Cassini].
* Helidon MP → Vidocq-MPS directement.
* `application.yaml` → MicroProfile Config (`vidocq.properties` ou env).
* Helidon Níma utilise déjà des virtual threads — la transition est conceptuellement transparente.

== Depuis Spring Boot

Spring Boot ne s'aligne pas naturellement sur le modèle MicroProfile, et la migration touche le programmation model.

[cols="1,1,2"]
|===
| Spring Boot | Vidocq-MPS | Note

| `@SpringBootApplication`
| `Vidocq.main(args)` + une classe quelconque
| Pas de classe d'application requise

| `@RestController`
| `@Path` + `@GET/@POST`
| Standard Jakarta REST

| `@Service`, `@Component`
| `@ApplicationScoped`
| CDI Lite

| `@Autowired`
| `@Inject`
| Constructor injection privilégiée

| `@ConfigurationProperties`
| `@VidocqConfig` + interface
| MicroProfile Config

| `application.yml`
| `vidocq.properties` + profils MP
| Préfixe `%<profil>.`

| Spring Data JPA
| xref:mansart::index.adoc[Mansart] (Jakarta Data 1.0)
| Repositories APT-générés
|===

== Depuis Open Liberty / WildFly

* `server.xml` → MicroProfile Config + extensions Vidocq-MPS.
* EAR → JAR autonome + plugin Maven.
* JNDI → CDI lookup via `Vauban.bootstrap()`.
* Annotations Jakarta — directement compatibles, le programming model reste identique.

== Depuis Payara Micro

Payara Micro et Vidocq-MPS partagent la cible MicroProfile. La principale différence est l'approche build-time : Payara Micro embarque GlassFish ; Vidocq-MPS produit un binaire jlink minimal sans serveur d'application classique.

* `payara-micro --deploy app.war` → `java -jar app-runner.jar`.
* `payara-micro.jar` (~ 80 Mo) → image jlink (~40 Mo).
* Tous les `feature.xml` MicroProfile activés sont remplacés par les extensions correspondantes côté Vidocq-MPS.
