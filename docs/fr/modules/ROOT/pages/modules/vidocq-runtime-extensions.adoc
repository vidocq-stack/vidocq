= vidocq-runtime-extensions
:description: Extensions built-in fournies avec Vidocq Runtime.

[.lead]
`vidocq-runtime-extensions` est l'ensemble des extensions livrées d'office, regroupées par domaine sous cinq agrégateurs (`essentials`, `jakartaee-core`, `jakartaee-web`, `microprofile`, `jpms-repackaged`). Chaque feuille est un artefact Maven indépendant, activé par simple ajout en dépendance par l'application utilisateur.

== Coordonnées

[cols="1,3"]
|===
| Artefact parent | `io.vidocq.runtime.extensions:vidocq-runtime-extensions:0.2.0`
| Source | `vidocq-runtime-extensions/`
|===

== Catalogue

[cols="2,1,3"]
|===
| Extension | Agrégateur | Rôle

| `vidocq-runtime-chappe-webserver-extension`
| `essentials`
| Branche xref:chappe::index.adoc[Chappe] comme transport HTTP/1.1, H2, H3. Bind configuré via `vidocq.http.host` / `vidocq.http.port`.

| `vidocq-runtime-migration-extension`
| `essentials`
| Façade de migration de schéma — exécute le moteur configuré avant l'ouverture de la datasource.

| `vidocq-runtime-flyway-migration-extension`
| `essentials`
| Migrations de schéma via Flyway.

| `vidocq-runtime-liquibase-migration-extension`
| `essentials`
| Migrations de schéma via Liquibase.

| `vidocq-runtime-cassini-rest-extension`
| `jakartaee-core`
| Branche xref:cassini::index.adoc[Cassini] pour Jakarta REST 4.0. Routage statique généré au build (artefact compagnon `-codegen`), CDI via Vauban.

| `vidocq-runtime-mansart-pool-extension`
| `jakartaee-web`
| Pool de connexions JDBC via xref:mansart::index.adoc[Mansart] Pool (compagnon `-datasources-codegen` pour les holders multi-datasources).

| `vidocq-runtime-mansart-data-extension`
| `jakartaee-web`
| Jakarta Data 1.0 via Mansart — scanne `@Repository`, implémentations générées par APT (compagnon `-codegen`).

| `vidocq-runtime-mansart-transactions-extension`
| `jakartaee-web`
| Gère `@Transactional` via `mansart-transactions` (compagnon `-codegen`).

| `vidocq-runtime-ravel-config-extension`
| `microprofile`
| {spec-mp-config} via xref:ravel::index.adoc[Ravel] — sources externes, profils, conversion typée.

| `vidocq-runtime-knock-health-extension`
| `microprofile`
| {spec-mp-health} via xref:knock::index.adoc[Knock] — endpoints `/q/health/{live,ready,started}`.

| `vidocq-runtime-dirac-metrics-extension`
| `microprofile`
| {spec-mp-metrics} via xref:dirac::index.adoc[Dirac] — endpoint Prometheus.

| `vidocq-runtime-grimm-openapi-extension`
| `microprofile`
| {spec-mp-openapi} via Grimm — document généré à la compilation (le compagnon `-ui` sert le visualiseur).

| `vidocq-runtime-cervantes-jwt-extension`
| `microprofile`
| MicroProfile JWT Auth via xref:cervantes::index.adoc[Cervantes].

| `vidocq-runtime-cyrano-rest-client-extension`
| `microprofile`
| MicroProfile REST Client via xref:cyrano::index.adoc[Cyrano] — proxys générés par APT.

| `vidocq-runtime-humboldt-telemetry-extension`
| `microprofile`
| MicroProfile Telemetry via xref:humboldt::index.adoc[Humboldt] — traces, métriques, logs, export OTLP/HTTP.
|===

CDI (xref:vauban::index.adoc[Vauban]) et JSON (xref:champollion::index.adoc[Champollion]) ne sont pas des extensions autonomes : Vauban est le moteur intégré à `vidocq-runtime-core`, et Champollion arrive transitivement avec l'extension REST.

Prévu : une extension Jakarta Servlet 6.1 branchant xref:foy::index.adoc[Foy] au-dessus de Chappe.

== Cycle de vie type — exemple Chappe

L'extension `vidocq-runtime-chappe-webserver-extension` illustre le pattern. Quatre points d'ancrage :

[cols="1,2,1,3"]
|===
| Phase | Acteur | Priorité | Action

| `configure`
| `ChappeEngineExtension`
| 100
| installe `ChappeMountPoint`

| `onStart`
| Contributeurs (REST, Servlet)
| 500–9999
| appellent `mount(...)`

| `onStart`
| `ChappeServerBootstrap`
| 10000
| démarre un `Server` par listener

| `onStop`
| `ChappeServerBootstrap`
| 10000
| arrête les serveurs proprement
|===

Les autres extensions suivent une logique d'ordonnancement comparable, avec leurs propres priorités.

== Activation par dépendance

Une extension est activée dès qu'elle est présente sur le module-path. Aucune annotation `@EnableX` n'est requise — l'index APT détecte le `provides VidocqExtension` JPMS.

[source,xml]
----
<dependency>
    <groupId>io.vidocq.runtime.extensions.jakartaee.core</groupId>
    <artifactId>vidocq-runtime-cassini-rest-extension</artifactId>
    <version>0.2.0</version>
</dependency>
----
