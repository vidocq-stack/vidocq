= Vidocq Runtime
:description: Serveur d'application MicroProfile Java 25 — orchestrateur ombrelle de l'écosystème Vidocq.

[.text-center]
image::vidocq-logo.png[Vidocq Runtime,300,role=module-logo]


[.lead]
Vidocq Runtime est le **runtime MicroProfile** qui assemble les six briques fondatrices de l'écosystème — xref:chappe::index.adoc[Chappe] (transport HTTP), xref:vauban::index.adoc[Vauban] (CDI), xref:champollion::index.adoc[Champollion] (JSON), xref:foy::index.adoc[Foy] (Servlet), xref:cassini::index.adoc[Cassini] (REST), xref:mansart::index.adoc[Mansart] (persistence) — en un runtime cohérent inspiré du modèle d'extensions Quarkus, mais sans ASM, sans réflexion runtime et sans Vert.x.

== Origine du nom

**Eugène-François Vidocq** (1775-1857), forçat évadé devenu fondateur et premier chef de la _Sûreté nationale_ (Brigade de la Sûreté, 1812). Précurseur de la criminologie scientifique, il fonde aussi la première agence de détectives privés. Voir https://fr.wikipedia.org/wiki/Eug%C3%A8ne-Fran%C3%A7ois_Vidocq[Wikipédia].

La métaphore est fidèle au rôle du module. Vidocq fédérait des indicateurs hétéroclites en une organisation policière moderne. Vidocq Runtime agrège six briques techniques disparates — chacune nommée d'après une autre figure historique — en un système cohérent. Le projet ombrelle prête son nom à l'écosystème entier.

== Différenciateurs

* **Java 25 + virtual threads** — `Executors.newVirtualThreadPerTaskExecutor()` partout, pas de pool de threads plateforme.
* **JPMS strict** — chaque artefact est un module nommé, `exports` minimaux, pas de classpath caché.
* **Génération statique** — Class-File API (JEP 484) + APT au compile-time, pas de proxy dynamique, pas d'ASM, pas de Byte Buddy.
* **Zéro réflexion runtime** — tout ce qui peut l'être est résolu au build, compatible AOT (GraalVM, Leyden CDS).
* **Build-time first** — comme Quarkus mais sur un socle CDI Lite + Class-File API standard JDK.
