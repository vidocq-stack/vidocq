= What's new
:description: Everything that changed in this component since the {release-version} release.

[.lead]
New in the `{project-version}` development line — everything listed here landed **after the {release-version} release** and is not part of it. Every entry links to the section that documents it, and those sections carry the [.tag-new]#NEW# badge. Each brick of the suite keeps its own page of this kind; xref:home::whats-new.adoc[the ecosystem index] gathers them. When the next release train ships, this page is frozen with it and restarts empty on the dev line.

* xref:migration.adoc#metrics-openapi-codegen[Fault Tolerance needs its codegen bundle] — `vidocq-runtime-heisenberg-fault-tolerance-extension-codegen` runs Heisenberg's processor on the application: the Fault Tolerance annotations are read from build-time companions, not by reflection, and the start-up warning _read by reflection_ goes away. `vidocq:checkpom` asks for it; `vidocq extension add` writes it.
* xref:testing.adoc#runtime-dependencies[`@VidocqTest` sees the runtime dependencies] — the application a test starts gets every `runtime`-scope jar on its module path, as `vidocq:dev` does: a JDBC driver is found without `requires`. The new `vidocq:test-path` goal, bound by `vidocq-runtime-parent`, names them for Surefire.
* xref:dev-services.adoc#host-log[Dev services log through the build] — under `vidocq dev`, `vidocq:run` and `vidocq:test`, a dev service logs one `[INFO]` line like the rest of the build, instead of the JDK's two-line format in the machine's language.
* xref:migration.adoc#metrics-openapi-codegen[Metrics and OpenAPI need their codegen bundle] — the Metrics and OpenAPI extensions ship a `-codegen` bundle that runs Dirac's and Grimm's processors on the application: metrics and the OpenAPI document come from build-time companions instead of a scan by reflection at start-up. `vidocq:checkpom` asks for both bundles.
* xref:dev-services.adoc[Dev services] — `vidocq-runtime-devservice-otel` starts an OpenTelemetry collector with Grafana (`grafana/otel-lgtm`) for an application with MicroProfile Telemetry, and publishes `otel.exporter.otlp.endpoint`; Grafana's URL is in the startup report and the dev console.
