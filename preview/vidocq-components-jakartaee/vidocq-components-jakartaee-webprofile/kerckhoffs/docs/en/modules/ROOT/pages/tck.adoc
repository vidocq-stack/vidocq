= Jakarta Security TCK
:description: How the official Jakarta Security 4.0 TCK is run on Kerckhoffs, and where it stands.

[.lead]
Kerckhoffs is measured against the official Jakarta Security 4.0 TCK (`jakartaee/security`, tag
`4.0.0-RELEASE`). The figures below are a *compatibility measurement*, never a certification: a
partial or local run does not certify anything.

The runtime column was measured on 2026-11-17, locally, with the runner of the Vidocq repository (`vidocq-runtime-tck-kerckhoffs-security`) on the commit `e0d61cdd` of the pull request that added the REST servlet mode (Vidocq/vidocq#634), which is `23331bda` on `main`; the Kerckhoffs commit was `3fe80a6`.

== How it runs

The TCK is published as sources only. `run-official-tck-security-4.0.sh` downloads the
distribution (SHA-256 pinned), builds it with its own Maven build and runs its Arquillian
tests on the Kerckhoffs container of the `kerckhoffs-tck` module (Foy, Chappe and Vauban)
instead of the GlassFish container. The deviations from an unmodified run are all on the Maven
command line and none is in the TCK sources; they are listed in `kerckhoffs-tck/BASELINE.md`.

[source,shell]
----
./run-official-tck-security-4.0.sh            # smoke set: the applications that are green
./run-official-tck-security-4.0.sh app-mem
----

=== Out of scope for now

The maintainer keeps the Jakarta Security 4.0 TCK *without JSF* for now. These applications are set aside, and
none of them is counted against the figures above.

[cols="3,3"]
|===
| Application | Why

| `app-mem-customform` | The only application that uses Jakarta Faces (JSF), with `@LoginToContinue`. Kerckhoffs has no JSF.
| `app-mem-form` (`AppMemFormImmediateIT` only) | `@LoginToContinue` with `*Expression` attributes. The interceptor is not written; no JSF is involved, the class is set aside with the annotation.
| `app-securitycontext`, `app-securitycontext-customprincipal` | The application uses an EJB.
| `app-db` | An EJB and a `@DataSourceDefinition` on an embedded database.
| `app-ldap`, `app-ldap2`, `app-ldap3`, `app-custom-identity-store-handler` | An embedded LDAP directory (`@LdapIdentityStoreDefinition` is milestone K4). `app-custom-identity-store-handler` is 4 of 5 on the Kerckhoffs container: the red test reads groups from the directory.
| `app-openid`, `app-openid2`, `app-openid3` | An OpenID Connect provider (milestone K5).
|===
