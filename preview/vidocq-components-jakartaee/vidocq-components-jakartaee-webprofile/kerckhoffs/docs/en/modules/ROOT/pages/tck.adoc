= Jakarta Security TCK
:description: How the official Jakarta Security 4.0 TCK is run on Kerckhoffs, and where it stands.

[.lead]
Kerckhoffs is measured against the official Jakarta Security 4.0 TCK (`jakartaee/security`, tag
`4.0.0-RELEASE`). The figures below are a *compatibility measurement*, never a certification: a
partial or local run does not certify anything.

== How it runs

The TCK is published as sources only. `run-official-tck-security-4.0.sh` downloads the
distribution (SHA-256 pinned), builds it with its own Maven build and runs its Arquillian
tests on the Kerckhoffs container of the `kerckhoffs-tck` module (Foy, Chappe and Vauban)
instead of the GlassFish container. The deviations from an unmodified run are all on the Maven
command line and none is in the TCK sources; they are listed in `kerckhoffs-tck/BASELINE.md`.

[source,shell]
----
./run-official-tck-security-4.0.sh            # smoke set: app-mem
./run-official-tck-security-4.0.sh app-mem
----

== Where it stands

[cols="1,1,3"]
|===
| Run | `app-mem` | Note

| 2026-11-14 | deployment refused | Nothing implemented: no `IdentityStoreHandler`.
| 2026-11-15 | 3 of 4 tests green | Identity stores are provided (K1). The three green tests expect an
unauthenticated caller; `testAuthenticated` waits for the HTTP authentication mechanism (K2).
|===

The other applications of the TCK need an EJB, a `DataSource`, an embedded directory or an
OpenID provider; they are added as the platform provides them. The `ci.tck.command` gate of the
pull requests is declared only once a smoke set is green.
