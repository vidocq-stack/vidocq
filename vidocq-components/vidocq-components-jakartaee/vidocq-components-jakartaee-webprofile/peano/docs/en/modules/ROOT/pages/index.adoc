= Peano
:description: Jakarta Expression Language 6.0 implementation — zero third-party dependency, native Java Modules, build-time accessors and compiled expressions.

[.text-center]
image::peano-logo.png[Peano,300,role=module-logo]

[.lead]
Peano is the Jakarta Expression Language 6.0 implementation of the Vidocq ecosystem, in pure Java 25: zero third-party dependency (only the `jakarta.el` spec jar), strict Java Modules, and — like every Vidocq brick — property accessors and expressions generated at build time where others reflect at run time.

== Origin of the name

Giuseppe Peano (1858–1932), the Turin logician who gave mathematics a rigorous formal notation — the `∈` symbol, the axioms of arithmetic that bear his name, the _Formulario mathematico_. See https://en.wikipedia.org/wiki/Giuseppe_Peano[the Wikipedia article].

Peano wanted expressions written in a notation without ambiguity, so that evaluating them became a mechanical act. That is the whole job of an Expression Language engine: parse `${order.total * 1.2}` into one unambiguous tree, then evaluate it the same way every time.

== What Peano implements

* *The language* — the grammar, operators and coercions of EL 6.0, functions, method expressions, method references,
  assignments, lambdas, list, set and map construction, and the lazy collection operations of chapter 2.
* *The API* — the `ExpressionFactory` provider, value expressions backed by resolvers (variables, imports, static
  fields), evaluation listeners and expression serialization.
* *Build-time code* — accessor tables written by an annotation processor (`@ELAccessible` or explicitly selected
  types), with direct resolver dispatch and direct public method calls, and adapters compiled for the
  `java.util.function` interfaces, `Runnable`, `Callable`, `Comparator` and selected application interfaces.

The known API limitations are recorded in
link:{repo-vidocq}/src/branch/main/vidocq-components/vidocq-components-jakartaee/vidocq-components-jakartaee-webprofile/peano/BUG.md[BUG.md].
All 361 official EL 6.0.1 TCK tests pass on Temurin 25, signatures included: a test result, not a certification
(see xref:tck.adoc[TCK status]).

== Three identifying traits

. **Zero third-party dependency** — the `jakarta.el` spec jar only. No Expressly, no Jakarta EL reference implementation, no parser generator: a hand-written lexer and recursive-descent parser.
. **Standard bootstrap** — `ExpressionFactory.newInstance()` and `ELProcessor` find Peano through the spec's `ServiceLoader` lookup. No Peano-specific API to learn.
. **Codegen-first** — accessor tables generated by an annotation processor replace reflective bean introspection, and expressions known at build time are compiled with the Class-File API. Reflection remains only as a documented, switchable fallback.

== Position in the ecosystem

Peano is a foundational brick: it depends on no other Vidocq module. Ibarra (Jakarta Pages 4.0) uses it to evaluate page expressions and compiles page expressions with it at build time. In the Vidocq runtime, the Pages extension adds a resolver of CDI bean names to the pages' EL context, so a page reads a `@Named` bean by its name (xref:{page-component-version}@vidocq::modules/vidocq-runtime-extensions.adoc#pages-cdi-beans[Vidocq Runtime — extensions]).
