[#final]
== Added in 0.4.0 (since 0.4.0-RC2)

* xref:reference.adoc#class-path-discovery[Peano is found on a class path] [.tag-new]#NEW# — `peano-core` lists its factory in `META-INF/services/jakarta.el.ExpressionFactory`, so `ExpressionFactory.newInstance()` finds Peano for an application or a test container on a class path, which failed with `Provider com.sun.el.ExpressionFactoryImpl not found`. The module path is unchanged.
* xref:reference.adoc#proxy-unwrapper-lifetime[A proxy unwrapper no longer keeps its application layer] [.tag-new]#NEW# — a `ProxyUnwrapper` that an application jar declares in `META-INF/services` stays registered as long as its class loader lives: under `vidocq dev`, it kept every discarded application layer reachable, one more class loader alive per hot reload (EL-025).

[#rc2]
== Brought by 0.4.0-RC2 (since 0.3.0)

* xref:internals.adoc#generated-code[Generated code and reflective fallback] — one table lists what Peano generates at build (accessor tables, the tables that serve client proxies, compiled expressions), what uses it at run time and what runs when it is missing, followed by when the reflective member access still runs and how `-Dpeano.reflection=deny` proves it does not.
* xref:reference.adoc#automatic-selection[Accessor tables without `@ELAccessible`] — the processor also generates tables for the `@Named` and `@Model` beans a page reaches by name and for the application types their properties, and those of explicitly selected types, hold; `-Apeano.autoAccessors=false` turns it off (EL-022).
* xref:reference.adoc#container-proxies[A bean's table serves its client proxy] — a normal-scoped bean reaches EL as its container's proxy; its generated table now serves it when a `ProxyUnwrapper` service names the bean class (EL-022).
* `MethodDescriptor` prints its parameter types and annotations by content instead of by array identity, and compares them by content: two descriptors of the same method print and compare equal (EL-021).
* The first expression factory no longer keeps the application layers `vidocq dev` discards on a hot reload: it holds no class loader and no accessor catalog, each context class loader gets its catalog once, and the catalog goes with its layer (EL-023).
