== Smoke and CI

In the monorepo a pull request runs no TCK. The `TCK nightly` workflow of the monorepo runs
`./run-official-tck-pages-4.0.sh --no-install all` (`ci.tck.command` of Ibarra's root POM) once a
day, on demand on a branch (tag `IBARRA`) and for a release, after installing Ibarra and its
upstream. The `smoke` selection of the script is a bounded regression subset and does not replace
the full `all` run. The complete command above, run from Ibarra's folder, is the acceptance check
for milestone I8.

Every Maven call of the script reads and writes `.tck-repository/` in Ibarra's folder
(`TCK_LOCAL_REPOSITORY` moves it), above `~/.m2/repository`, which it only reads: the install of
a branch never replaces the published Ibarra snapshot the other builds of the machine resolve.

== Runner

`ibarra-tck` enters the reactor only under `-Ptck`; official artifact scanning
requires `-Ptck,tck-official`. The official distribution is
`jakarta.tck:jakarta-pages-tck:4.0.0`, published by Eclipse rather than Maven
Central. Preparation preserves its embedded POM, supplies the omitted JavaTest
5.0 dependency and checks artifact SHA-256 digests.

The adapter is the published `ibarra-arquillian` module, which `ibarra-tck` takes at
`test` scope. It precompiles pages before launching modular Foy/Chappe. The server
contains neither the compiler nor `java.compiler`, and retains reflection denial.
It supports isolated WARs and filesystem resources. Root JSP property groups reach
the compiler through build-side descriptor parsing. Explicit deployment
precompilation preserves per-page translation failures as error servlets so valid
pages and negative translation tests can coexist; normal packaging still rejects
translation errors.

See xref:modules/official-tck-runner.adoc[Official TCK runner] for dependencies,
commands, artifact preparation and retained logs, and
xref:modules/arquillian-adapter.adoc[Arquillian adapter] for the deployment model,
its configuration and its limits.
