# Bodoni B2 — `fmt:` i18n and formatting — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement the Jakarta Standard Tag Library 3.0 `fmt:` library (spec §8 i18n and §9 formatting): twelve classic tag handlers, their TLDs under `jakarta.tags.fmt` and the legacy `http://java.sun.com/jsp/jstl/fmt` URI, and prove that real pages using them render on Ibarra.

**Architecture:** Spec algorithms that need no tag tree live in `io.vidocq.bodoni.core.internal` (`Locales`, `I18n`): locale parsing, preferred locales, resource bundle determination (§8.3), response encoding (§8.4) and formatting locale lookup (§9.3). The tag-tree rules (enclosing `<fmt:bundle>` / `<fmt:timeZone>`, §9.2, §9.4) live in a package-private `FmtSupport` next to the handlers in `io.vidocq.bodoni.core.tags.fmt`. Configuration goes through the API's `jakarta.servlet.jsp.jstl.core.Config` (`find`, `set`), never through a Bodoni-specific store.

**Tech Stack:** Java 25 (`java.text`, `java.util.ResourceBundle`), Java Modules, Maven 3.9.16, JUnit 6, `jakarta.servlet.jsp.jstl-api` 3.0.2 (compile), Pages 4.0 / Servlet 6.1 / EL 6.0 APIs (provided).

**Spec:** `PLAN.md` (design of record, milestone B2, open question 4) and the Jakarta Standard Tag Library 3.0 specification, chapters 8 and 9, <https://jakarta.ee/specifications/tags/3.0/jakarta-tags-spec-3.0.html>. Each task cites the sections it implements; read them before writing the test.

## Decisions taken with the maintainer (2026-10-22)

| Topic | Decision |
|---|---|
| Bundle lookup (open question 4) | `ResourceBundle.getBundle(basename, locale, loader, control)` with `loader` = the thread context class loader, or the system class loader when it is `null`: the same loader the API's `LocaleSupport` uses, so `fmt:message` and `LocaleSupport.getLocalizedMessage` agree. Evidence (JDK 25, 2026-10-22): from a library module, a bundle in an encapsulated package of a named application module is invisible through every overload, including `getBundle(String, Locale, Module)` on behalf of the page's module; an `opens`ed package, a jar-root or non-package directory (`i18n-bundles/`), and any class-path location are visible. The Reference page documents the three placements for a named application module: `opens` of the bundle package, root or non-package directory, or an application-supplied `LocalizationContext` (no `opens`). A module-aware lookup is deferred to `bodoni-ibarra` (B6), where generated code runs inside the application module. |
| URIs | `jakarta.tags.fmt` **and** the JSTL 1.2 URI `http://java.sun.com/jsp/jstl/fmt`, same classes (B1 rule). Not the 1.0 `fmt` / `fmt_rt` URIs. |
| Date types | `java.util.Date` only, as the spec types `fmt:formatDate value`. No `java.time` extension in B2. |
| Scope | One PR for all of B2. |

## Review Focus

1. **A handler instance reused across invocations** (Jasper and Open Liberty pool classic handlers; Ibarra does not): `fmt:message` parameters, `fmt:formatNumber` digit and grouping settings, a `parseLocale` or `timeZone` from the previous use. Each stateful handler's test runs it twice on the same instance with different attributes.
2. **Locale data is the JDK's CLDR data, not the spec's 2001 examples**: French grouping uses U+202F (`345 987,246`), long date and time styles change between JDK releases. Tests compare locale-styled output with what `java.text` produces for the same locale, style and time zone; only patterns and the spec examples verified below are hard-coded.
3. **Strict date parsing (§9.10 "non-lenient")**: `"4/13/02x"` and `"2/30/02"` with `pattern="M/d/yy"` must raise a `JspException` that names the value, not return a date.
4. **Browser locales in order (§8.3.2)**: preferred `en`, `fr_CA` with bundles `_en` and `_fr_CA` selects `_en` (language match beats a later exact match); the JVM default locale is never consulted.
5. **No session created by i18n actions (§8.4)**: the charset goes to the session only "if a session exists"; a page without a session must not get one from `fmt:setLocale`.
