# Bodoni B3 — `x:` XML library — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement the Jakarta Standard Tag Library 3.0 `x:` library (spec §11 XML core, §12 XML flow control, §13 XML transform): ten classic tag handlers on the JDK's `java.xml` only, their TLDs under `jakarta.tags.xml` and the legacy `http://java.sun.com/jsp/jstl/xml` URI, a "same origin" policy for every external reference an XML or XSLT document makes, and proof that real pages using them render on Ibarra.

**Architecture:** JDK plumbing with no tag tree lives in `io.vidocq.bodoni.core.internal`: hardened factories (`XmlFactories`), the external-reference policy (`SystemIdPolicy`, an `EntityResolver2` and `URIResolver`), XPath evaluation over the page scopes (`XPathEngine`, `PageVariableResolver`, `XPathScopes`, `NodeSet`) and document inputs (`XmlDocuments`). The handlers live in the exported `io.vidocq.bodoni.core.tags.xml`, with two package-private helpers (`XmlSupport` for the `x:forEach` context node and failures, `DocumentTagSupport` for the doc-or-body skeleton of `x:parse` / `x:transform`). `x:forEach` and the two `c:` iterators share a new public `tags.core.RangeLoopTagSupport`.

**Tech Stack:** Java 25 (`javax.xml.parsers`, `javax.xml.transform`, `javax.xml.xpath`, `org.w3c.dom`, `org.xml.sax`), Java Modules, Maven 3.9.16, JUnit 6, `jakarta.servlet.jsp.jstl-api` 3.0.2 (compile), Pages 4.0 / Servlet 6.1 / EL 6.0 APIs (provided).

**Spec:** `PLAN.md` (design of record: "`x:` — XML with the JDK only", milestone B3, open question 6) and the Jakarta Standard Tag Library 3.0 specification, §2.3, §2.7, §11, §12, §13, <https://jakarta.ee/specifications/tags/3.0/jakarta-tags-spec-3.0.html>. Each task cites the sections it implements; read them before writing the test.

## Decisions taken with the maintainer (2026-10-23)

| Topic | Decision |
|---|---|
| XML hardening (open question 6) | **Same origin.** `XMLConstants.FEATURE_SECURE_PROCESSING` true on every `DocumentBuilderFactory`, `SAXParserFactory`, `TransformerFactory` and `XPathFactory` Bodoni creates (JDK expansion limits, no XSLT/XPath extension functions). DTD validation off; a DOCTYPE with an internal subset is accepted (`disallow-doctype-decl` is **not** set: TCK `positiveParseNoDTDValidationTest`). Bodoni resolves every external reference itself (`EntityResolver2` for external entities and the external DTD subset, `URIResolver` for `xsl:import`, `xsl:include`, `document()`) and hands the JDK an opened stream: the JDK never fetches on its own. Without a system id every external reference is refused. With an absolute system id a target must have the same scheme, host and port (scheme and host compared case-insensitively, default port normalised); absolute targets open with `URL.openConnection()`, HTTP redirects off, a 3xx is a failure. With a relative system id (§11.1.7) targets stay inside the web application (`ServletContext.getResourceAsStream`), absolute targets are refused. A refused or failed reference ends the action with a `JspException` naming the reference and the system id, cause kept. Must pass: TCK `positiveParseSystemIdTest`, `positiveTransformDocSystemIdTest`, `positiveTransformXmlAndXmlSystemIdTest`, `positiveTransformXsltSystemIdTest`. |
| URIs | `jakarta.tags.xml` **and** `http://java.sun.com/jsp/jstl/xml`, same classes (`x.tld`, `x-1_2.tld`). Not the 1.0 `xml` / `xml_rt` URIs. No `<validator>` (B1 precedent). |
| Package | `io.vidocq.bodoni.core.tags.xml`, exported. |

## Rulings of this plan

| Topic | Ruling | Why |
|---|---|---|
| `java.xml` | `requires transitive java.xml` | Bodoni uses it directly, and exported signatures expose `org.xml.sax.XMLFilter` and `javax.xml.transform.Result`. Today the API module reaches `java.xml` only through `java.desktop` (open question 3); Bodoni must not depend on that chain. |
| Relative system id base | Given to the parser as `bodoni-webapp:<context-relative path>` (`SystemIdPolicy.WEBAPP_SCHEME`) | The JDK expands a relative base against the JVM working directory; a private absolute scheme keeps expansion inside the web application and distinguishes web-app targets from `file:` ones. |
| Relative system id path | Leading `/`: context-relative. Otherwise relative to the directory of the current page: the request attribute `jakarta.servlet.include.servlet_path` when set, else `HttpServletRequest.getServletPath()` | Same result as B1's `c:import`, whose `RequestDispatcher` resolves page-relative paths against the current (or included) page. |
| Origin of a reference | Fixed when the policy is built, from the page's system id; the base the parser or XSLT processor passes is used only to resolve the reference, never to widen the origin | An `xml:base` in an untrusted document changes the base `document()` receives. |
| `jar:` and other opaque system ids | Every reference refused | A relative reference cannot be resolved against an opaque URI. |
| JDK access properties | `ACCESS_EXTERNAL_DTD`, `ACCESS_EXTERNAL_SCHEMA` (parsers) and `ACCESS_EXTERNAL_STYLESHEET` (XSLT) set to `""` explicitly, if Task 1's probe confirms a resolver-supplied stream still passes; else `"all"` | A system property or `jaxp.properties` cannot reopen JDK-side fetching; Bodoni's resolvers never return `null`. |
| Parsing | Namespace-aware (`newDefaultNSInstance`), XInclude off, error handlers that throw on errors and drop warnings (no `System.err` output) | XPath 1.0 semantics; no console noise. |
| Exported types | `x:parse` `var` and `varDom`: the `org.w3c.dom.Document`. `x:set` node-set: an immutable `internal.NodeSet implements NodeList`. `x:forEach` `var`: the current `org.w3c.dom.Node` | The JDK's XPath takes `Node` and `NodeList` variables as node-sets (§11.1.3). |
| Java → XPath | `Boolean`, `String`, `Node`, `NodeList` as is; `Number` → `Double`; any other object → `String.valueOf` | §11.1.3 leaves other types implementation-defined; the JDK has no number mapping for `Integer`. |
| `$sessionScope:` without a session | Unbound (the evaluation fails), no session created | Same rule as B2's i18n actions. |
| `x:choose` / `x:when` / `x:otherwise` | Own small classes in `tags.xml` | `x:when` must check for an `x:choose` parent; `c:choose`'s branch state is package-private in `tags.core`, and page code cannot call public members inherited from a class in a non-exported package. The classes stay below Sonar's duplication threshold. |
| `begin` / `end` / `step` | New public abstract `tags.core.RangeLoopTagSupport extends LoopTagSupport`, used by `c:forEach`, `c:forTokens` and `x:forEach` | Removes the existing duplication between the two `c:` iterators and avoids a third copy. |
| `x:transform` | `result` attribute when set, else `var`, else the page. A page-supplied `Source` is passed as is. A `null` `x:param` value sets no parameter. | The spec offers `var` and `result` as alternatives and is silent on the rest. |
| Readers | A page-supplied `Reader` is never closed by Bodoni | The page owns it. |

## Review Focus

1. **Entity expansion bomb** (nested internal entities, "billion laughs") in a page-supplied document: the action fails with a `JspException` in well under a second, never an `OutOfMemoryError`. Test in Task 4.
2. **A base that tries to widen the origin**: `document()` or an import whose base an untrusted `xml:base` points at another host must be refused; the policy's origin comes from the page's system id only. Test in Task 2.
3. **Percent-encoded traversal** (`%2e%2e/%2e%2e/WEB-INF/x`, `..%2f`) from a relative system id: refused, never served from outside the context root. Test in Task 2.
4. **A handler instance reused across invocations** (Jasper and Open Liberty pool classic handlers): `x:param` values of the previous `x:transform`, the body of the previous `x:parse`, a `branchTaken` of the previous `x:choose`. Each stateful handler's test runs it twice on the same instance, without calling the setters again.
5. **No session created by an XPath variable**: `$sessionScope:x` on a page without a session fails as unbound and leaves `request.getSession(false)` `null`. Test in Task 3.

  5. the returned `InputSource` (or `SAXSource`) carries the stream and `target.toString()` as system id.
- Messages (constants, exact): refused → `"<action>: external reference '<r>' refused, system id '<systemId or (none)>': <reason>"`; read failure → `"<action>: external reference '<r>' cannot be read, system id '<systemId or (none)>': <cause message>"`, the cause kept.
