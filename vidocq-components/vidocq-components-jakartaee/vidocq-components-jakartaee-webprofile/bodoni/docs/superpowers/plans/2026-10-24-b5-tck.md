# Bodoni B5 — official Jakarta Tags TCK runner (`bodoni-tck`) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add `bodoni-tck`, a runner of the official Jakarta Tags TCK (`jakarta.tck:tags-tck:11.0.3`) on Bodoni + Ibarra + Foy + Peano, with its script and smoke check, run the whole suite once and record the result in `bodoni-tck/BASELINE.md`, every failing class triaged.

**Architecture:** `bodoni-tck` joins the reactor only under `-Ptck`. The official classes resolve only under `-Ptck,tck-official`, and Surefire runs them on the class path. Each WAR is deployed by Ibarra's published Arquillian adapter (`ibarra-arquillian`, test scope), which puts Bodoni, the JSTL API and H2 in the application layer through three `arquillian.xml` properties. A JUnit Platform `LauncherSessionListener` in the test JVM loads the official Derby DDL into an in-memory H2 database, serves it over H2's TCP server on an ephemeral loopback port, and publishes the four `jstl.db.*` client properties. The script `run-official-tck-tags-3.0.sh` fetches that DDL from the official zip, after checking its SHA-256.

**Tech Stack:** Java 25, Maven 3.9.16, JUnit 6.0.3 (Platform launcher API), Arquillian 1.9.4.Final (JUnit 5 container), ShrinkWrap 1.2.6, `io.vidocq.ibarra:ibarra-arquillian:0.4.0-SNAPSHOT`, H2 2.3.232, bash + curl + unzip + `shasum`/`sha256sum`, Forgejo Actions.

**Spec:** the brief `…/scratchpad/b5-plan-brief.md` (maintainer decisions of 2026-10-23); `PLAN.md` ("TCK plan", milestone B5, open questions 1 and 2, "Open interpretations" of B3 and B4); Ibarra's `ibarra-arquillian/README.md` and `docs/en/modules/ROOT/pages/modules/arquillian-adapter.adoc` ("Using it from another project"); the models `ibarra/main/{run-official-tck-pages-4.0.sh, ibarra-tck/pom.xml, ibarra-tck/BASELINE.md}` and `peano/main/{run-official-tck-el-6.0.sh, peano-tck/pom.xml}`.

- **The suite** (`tags-tck-11.0.3.jar`, extracted): 50 `JSTLClientIT` classes, **541** `@Test` methods (counted with `javap -v`, none `@Disabled`), 579 JSPs. Per class: `compat/onedotzero` 38; `core`: cwo 9, iftag 6, catchtag 2, outtag 7, remove 1, set 8, foreach 24, fortokens 15, loopstatus 1, importtag 23, param 7, redirect 4, url 8; `etu`: config 6, functions 64, tlv/permitted 2, tlv/scrfree 8, uri 1; `fmt`: fmtdate 14, fmtnum 19, localecontext 4, parsedate 18, parsenum 14, settimezone 6, timezone 2, bundle 6, message 17, param 2, requestencoding 4, resourcelookup 2, responseencoding 2, setbundle 7, setlocale 6; `sql`: param 21, query 26, result 8, setdatasource 22, transaction 19, update 21; `xml`: xcwo 8, xforeach 9, xif 7, bindings 1, parse 15, types 2, xout 4, xset 6, xtransform/param 3, transform 12. The embedded POM brings Arquillian `arquillian-junit5-core`, `arquillian-container-test-api`, `arquillian-test-api` 1.9.4.Final, ShrinkWrap API 1.2.6, `jakarta.tck:common` 11.1.1, `commons-httpclient` 3.1, `ant` 1.10.15, `junit-jupiter-api` 5.11.4 (overridden by `vidocq-parent`'s JUnit 6.0.3; the Pages TCK, also on `arquillian-junit5`, passes 682/682 in `ibarra-tck` under the same parent).
- **Every class** calls `archive.addAsLibrary(getCommonJarArchive())`. `getCommonJarArchive()` does `addPackages(true, "com.sun.ts.tests.jstl.common")`, so every WAR holds `com.sun.ts.tests.jstl.common.resources`. The `applicationOpens` deployment check (absent package → failed deployment) therefore holds for all 50 WARs. The jar also carries `common.client` classes whose supertypes (`jakarta.tck:common`) are not in the WAR. They are never loaded server-side.
- **Filters and listener**: `JstlDbFilter` and `SQLContextListener` sit in `jstltck-common.jar` (`WEB-INF/lib`). `PagesContainer.extract` runs `WarLibraries.assemble` (libraries expanded into the application classes) before `generateComponents`, so they get direct factories (Ibarra plan Review Focus 5, pinned by `webXmlFilterFromAWarLibraryGetsADirectFactory`). The application layer has one class loader (`defineModulesWithOneLoader`), so `Class.forName("org.h2.Driver").newInstance()` and `DriverManager.getConnection` in `TckDataSourceWrapper` see H2.
- **JDK modules**: the host boot layer reaches `java.desktop` (`jakarta.servlet.jsp` `requires transitive java.desktop`), `java.xml` (Foy) and `java.net.http` (Chappe). `java.sql`, `java.naming` (Bodoni, JSTL API) and `jdk.localedata` (a service provider no `requires` reaches) must be added: `jdkModules=java.sql,java.naming,jdk.localedata`.
- **Database properties**: `SqlUrlClient.setup` and `CompatAbstractUrlClient.setup` assert that `jstl.db.url`, `jstl.db.user`, `jstl.db.password`, `jstl.db.driver` are non-empty system properties, then send them as request headers. Without them, the 155 tests of `sql/*` and `compat/onedotzero` fail in `@BeforeEach`. `JstlDbFilter` escapes commas in the URL. The JDBC-string pages join `url,driver,user,password` unescaped, so the URL must have no comma.
- **DDL**: the zip's `tags-tck/sql/<db>/<db>.ddl.jstl.sql` holds the schema **and** the rows. `<db>.dml.jstl.sql` is the statement catalogue, and the jar already ships it in every sql package as `tssql.stmt`. That `tssql.stmt` is `derby.dml.jstl.sql` byte for byte plus a licence header, so the pages speak Derby SQL: the runner loads `derby.ddl.jstl.sql`. That file has 3 `drop table`, 3 `create table` and 14 `INSERT`s, with `{d …}`/`{t …}`/`{ts …}` escapes and a `rank` column.
- **H2 probe** (`scratchpad/b5probe/DbProbe.java`, H2 2.3.232, JDK 25). The Derby DDL loads unchanged in H2's default mode (no `MODE`, no `NON_KEYWORDS`): 17 statements succeed, and only the 3 `drop table` fail, on a fresh database. `Server.createTcpServer("-tcpPort", "0").start().getPort()` returns the bound ephemeral port. A second JVM connecting to `jdbc:h2:tcp://127.0.0.1:<port>/mem:jstl` as `jstl`/`jstl` reads the 10 rows of `jstl_tab1` and `dob=1999-05-05`, `rank=1`, inserts with JDBC escapes, and sees isolation `2` (`READ_COMMITTED`).
- **Zip**: <https://download.eclipse.org/jakartaee/tags/3.0/jakarta-tags-tck-3.0.0.zip>, 15,320,600 bytes. Its published `.sha256` is `996c9abc6561134cea986107da0648c2a33277d2f765475994ff9b16da70cb5a`, which matches the local copy. Licence: EFTL 1.0 (zip `LICENSE.md`). The Central jar ships an EFTL 1.1 `LICENSE.md`, and its POM declares EPL-2.0 / GPL-2.0 with Classpath Exception.
- **Time zone**: the formal `ts.jte` sets `tz=US/Eastern` for its harness. No TCK page prints a date in the server's default zone: the 7 date pages without an explicit zone (`positiveFDVarTest`, `negativeFDScopeNoVarTest`, `positivePDVarTest`, `positivePDScopeTest`, `negativePDScopeNoVarTest`, `negativePDUnableToParseValueTest`, `positivePDValueNullEmptyTest`) only check a type or an error. The adapter's `ProcessBuilder` inherits the environment (it sets no `environment()`), so a `TZ` variable reaches the host.
- **JSTL 1.0 URIs in the suite**: `_rt` URIs in `compat/onedotzero` (38 pages), `etu/tlv/scrfree` (`core_rt`, 5 pages) and `sql/update` (`sql_rt`). Decision 4 covers the four `_rt` TLDs only.
- **B3/B4 interpretations**:
  - Empty `x:forEach select`: `spec.xml.xconditional.xforeach.JSTLClientIT#positiveForEachSelectEmptyTest` **runs**, and its page expects no body evaluation.
  - `startRow < 0`: not exercised (the one `startRow` page, `positiveQueryStartRowAttributeTest`, uses `1`).
  - Blank `maxRows` setting: not exercised (the config pages set `invalid`, `-5`, `5` and an `Integer`).

## Review Focus

1. **The database properties are missing or blank** (the DDL was not fetched, or `--no-prepare` after a `clean`). Expected: the run stops before Maven with a message naming the script and the flag, never a "full run" where all 155 sql/compat tests fail in `@BeforeEach`. Tests: Task 3 `noPrepareNeedsThePreparedDdl`, Task 2 `missingDdlFailsNamingTheFileAndTheScript`.
2. **A JDBC URL with a comma, or a blank credential.** The JDBC-string pages split on commas, and `SqlUrlClient` refuses empty values. Expected: the URL matches `jdbc:h2:tcp://127\.0\.0\.1:\d+/mem:jstl`, and user, password and driver are non-empty. Test: Task 2 `clientPropertiesAreNonEmptyAndTheUrlHasNoComma`.
3. **`--no-install` after editing `bodoni-core`.** Expected: refusal, exit 2, no Maven run against the stale snapshot. Tests: Task 3 `noInstallRefusesAStaleSnapshot`, `noInstallRefusesAMissingSnapshot`.
4. **A zip that is not the official one** (a mirror, a truncated download, a `TAGS_TCK_ZIP` pointing elsewhere). Expected: `checksum mismatch`, exit 1, nothing extracted, no Maven run. Test: Task 3 `prepareRefusesAZipWithAnotherChecksum`.
5. **State left by an earlier start in the same JVM** (a failed start, a second session). Expected: a failed start releases the TCP port, and a new start sees only the DDL's rows. Tests: Task 2 `failingStatementOtherThanDropStopsTheStart`, `restartGivesAFreshDatabase`.
