== Running it

Prerequisites: Java 25 and Maven 3.9.16 (`sdk env`), and network access for the first download of the distribution zip, unless `TAGS_TCK_ZIP` names a local copy (a relative path is resolved against the current directory). The script checks the zip against a pinned SHA-256 and extracts the Derby DDL only, into `bodoni-tck/target/tags-tck-distribution/`. It never copies a TCK file into the repository (EFTL).

[source,bash]
----
sdk env
./run-official-tck-tags-3.0.sh                 # smoke (the default): eight whole classes
./run-official-tck-tags-3.0.sh all             # every official class
./run-official-tck-tags-3.0.sh -Dtest=com.sun.ts.tests.jstl.spec.sql.query.JSTLClientIT
./run-official-tck-tags-3.0.sh --help
----

[cols="1,3",options="header"]
|===
| Argument | Effect

| `smoke` | Eight whole classes: one per library, the URI check, the JSTL 1.0 compatibility class and the `c:choose` structure class (see <<smoke>>). The default.
| `all` | `-Dtest=com.sun.ts.tests.jstl.**.*IT`: every official class.
| `-Dtest=…` | A Surefire selection of official classes or methods.
| `--no-prepare` | Reuses the DDL already extracted; refused (exit 2) when it is absent, so that the `sql` and compatibility classes cannot fail in their setup unnoticed.
| `--no-install` | Skips the `./mvnw clean install` of `bodoni-core` and `bodoni-peano` (the only modules the runner needs, so the Open Liberty IT is not run); refused (exit 2) when the installed `bodoni-core` or `bodoni-peano` snapshot is missing or older than its sources, its `pom.xml` or the root `pom.xml`.
| Other arguments starting with `-` | Passed to the last Maven call (write an option value attached to it: `-T4`, `-Dkey=value`).
|===

The script first runs the runner's own tests (`./mvnw -ntp -Ptck -pl bodoni-tck test`), then the official classes (`-Ptck,tck-official`). Before Maven runs it deletes `bodoni-tck/target/surefire-reports` and `bodoni-tck/target/pages-deployments`, so a partial selection cannot be mistaken for a full run. The Surefire reports land in `bodoni-tck/target/surefire-reports/`; each deployment keeps its `server.log` and `translation-errors.txt` under `bodoni-tck/target/pages-deployments/war-*/`.

The host processes inherit the machine's time zone and locale. To check whether a failure depends on the zone, rerun it with `TZ=UTC ./run-official-tck-tags-3.0.sh -Dtest=…`: the Surefire JVM and the forked hosts both inherit `TZ`.

== How it is wired

* **Module and profiles.** `bodoni-tck` is a module of the root `tck` profile only, and is not published. `-Ptck` runs its own tests (its Arquillian configuration, the database, the script); `-Ptck,tck-official` adds the official jar and scans its `*IT` classes. A plain `./mvnw -ntp clean install` neither builds the runner nor resolves anything TCK-related.
* **Adapter.** The published `io.vidocq.ibarra:ibarra-arquillian` adapter, at test scope, precompiles each WAR with Ibarra and runs it on modular Foy over Chappe in its own process. Foy, Peano and Chappe come from the adapter, on the versions Ibarra uses. Arquillian, ShrinkWrap and the TCK clients are not Java modules, so the clients run on the test class path; what the adapter deploys stays modular (named `tck.application` and `tck.host` modules, `--limit-modules`).
* **Adapter properties** (`bodoni-tck/src/test/resources/arquillian.xml`):
** `applicationLibraries` = `io.vidocq.bodoni.core,io.vidocq.bodoni.peano,jakarta.servlet.jsp.jstl,com.h2database`: Bodoni's handlers and TLDs, its Peano accessor tables under `peano.reflection=deny`, the JSTL API, and the H2 driver, all in the one class loader of the application layer, so the TCK's `Class.forName("org.h2.Driver")` and `DriverManager` see H2.
** `jdkModules` = `java.sql,java.naming,jdk.localedata`: the host boot layer does not reach them on its own; Bodoni and the JSTL API require the first two, and `jdk.localedata` is a locale-data provider no `requires` reaches.
** `applicationOpens` = `com.sun.ts.tests.jstl.common.resources`: every TCK WAR carries the TCK's common jar, whose resource bundles `fmt:` loads by name.
* **Database.** The `sql` and compatibility classes need three tables. The runner loads the Derby DDL of the official zip (`tags-tck/sql/derby/derby.ddl.jstl.sql`, the schema and its rows), unchanged, into an in-memory H2 2.3.232 database, without a compatibility mode. A JUnit Platform `LauncherSessionListener` starts it once per test JVM when the `bodoni.tck.ddl` system property names the DDL (set by `tck-official` only), serves it through an H2 TCP server on an ephemeral port bound to `127.0.0.1` (`h2.bindAddress`), and sets the `jstl.db.url`, `jstl.db.user`, `jstl.db.password` and `jstl.db.driver` system properties the TCK clients send to the pages. One database per run: state carries from class to class, as in the formal harness, and a single-class rerun starts fresh.
* **No parallel execution** (`junit.jupiter.execution.parallel.enabled=false`): the adapter keeps its deployments in one unsynchronised map.

The test tooling dependencies are listed in xref:reference.adoc#test-tooling[Reference].

== Results

Both runs on 2026-10-24 (Temurin 25, macOS arm64, zone `Europe/Paris`), with `./run-official-tck-tags-3.0.sh all`. The second run, after the TCK fixes, used Peano and Ibarra built from their `main` branches (Peano with the COMP-010 fix of https://codefloe.com/Vidocq/peano/pulls/61[Vidocq/peano#61]).

The TCK client reports every failed check as an error, never as a failure. By library, first run: `c` 111/115, `fn` and the extension tests 77/81, `fmt` 114/123, `sql` 86/117, `x` 62/67, JSTL 1.0 compatibility 2/38; after the fixes, every library is at 100 %.

What 541/541 means: on this stack (Bodoni's standard handlers, every page precompiled by Ibarra, run on Foy and Peano with `peano.reflection=deny`), every test of the Tags suite of the Jakarta EE 11 Platform TCK passes. It is not a certification and does not say how Bodoni behaves on another container; the Open Liberty portability proof is milestone B7.

The causes of the first run's 89 errors, all fixed:

[cols="3,1,1,2",options="header"]
|===
| Cause | Owner | Tests | Fix

| JSTL 1.0 `_rt` URIs not shipped | known decision | 40 | The four JSTL 1.0 request-time TLDs (`c_rt`, `fmt_rt`, `sql_rt`, `x_rt`) on the 3.0 handlers
| A constant `${…}` on a deferred-value attribute: Peano's compiled constant expression lacked the `(ELContext, Class)` constructor (COMP-010) | Peano | 32 | https://codefloe.com/Vidocq/peano/pulls/61[Vidocq/peano#61]; Ibarra regression test IBARRA-156, https://codefloe.com/Vidocq/ibarra/pulls/64[Vidocq/ibarra#64]
| Translation-time constraints not enforced (BOD-006) | Bodoni | 9 | Tag library validators for `c`, `fmt`, `sql` and `x`, run by Ibarra at page `init()`
| `LocalizationContext` unreadable under `peano.reflection=deny` (BOD-007) | Bodoni | 3 | A `LocalizationContext` accessor table in `bodoni-peano`
| `fmt:message` with `bundle` does not set the response locale (BOD-008) | Bodoni | 2 | The `bundle` attribute sets the response locale (§8.4)
| `c:forTokens` does not accept a deferred `items` (BOD-009) | Bodoni | 1 | `items` accepts a deferred value (§6.3)
| `fmt:parseDate` refused the text after a complete date (BOD-010; first triaged as TCK input on JDK 20 and later, a wrong diagnosis) | Bodoni | 2 | Text after a complete date is ignored, as `DateFormat.parse(String)` does; with BOD-011, an ASCII space matches the U+202F of a JDK 20+ style
|===

The Bodoni defects are tracked in link:{repo-bodoni}/src/branch/main/BUG.md[BUG.md]. Per-class results of both runs, evidence, the resolved snapshots, the passing tests worth a note and the upstream items: link:{repo-bodoni}/src/branch/main/bodoni-tck/BASELINE.md[`bodoni-tck/BASELINE.md`].

The four interpretations Bodoni recorded in B3 and B4 are not settled by this suite: the 11.0.3 `x:forEach` class has no test that requests its empty-`select` page, and `startRow < 0`, a blank `maxRows` setting and `limitedByMaxRows` at exactly `maxRows` rows are not exercised.

== Smoke and CI

`./run-official-tck-tags-3.0.sh smoke` runs eight classes, 138 tests (138/138 after the TCK fixes): `compat.onedotzero` (the JSTL 1.0 request-time URIs, with the `sql` database), `spec.core.conditional.cwo` (the `c:choose` rules of the tag library validators), `spec.core.general.remove` (`c`), `spec.etu.functions` (`fn`), `spec.etu.uri`, `spec.fmt.i18n.param` (`fmt`), `spec.sql.setdatasource` (`sql`, through the H2 database) and `spec.xml.xmlcore.bindings` (`x`). The `official-tags-tck-smoke` check (`.forgejo/workflows/tck-tags.yml`) runs it on every pull request and push to `main`, and is a required check of `main`: a pull request that breaks the smoke set cannot be merged. The smoke set is a regression subset; the full `all` run is not in CI.
