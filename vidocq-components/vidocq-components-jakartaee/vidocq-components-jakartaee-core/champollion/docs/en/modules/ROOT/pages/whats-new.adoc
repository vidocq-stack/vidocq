= What's new
:description: Everything that changed in this component since the {release-version} release.

[.lead]
New in the `{project-version}` development line — everything listed here landed **after the {release-version} release** and is not part of it. Every entry links to the section that documents it, and those sections carry the [.tag-new]#NEW# badge. Each brick of the suite keeps its own page of this kind; xref:home::whats-new.adoc[the ecosystem index] gathers them. When the next release train ships, this page is frozen with it and restarts empty on the dev line.

* `champollion-jsonb-cdi` is container-neutral: its Vauban glue moved to a new module, `champollion-jsonb-cdi-vauban`, which the Vidocq REST extension brings (xref:reference.adoc#jsonb-cdi[JSON-B and CDI]).
* xref:reference.adoc#jsonb-cdi-generic-beans[Generic and qualified adapters are the container's beans] [.tag-new]#NEW# — an adapter, serializer or deserializer whose class has a bounded type variable (`MyAdapter<T extends Number>`), or whose bean has only a qualifier of its own, is served as the container's bean, by the registry and without it. It was created with `new`, without its injections or lifecycle callbacks and without a word, and the build compatible extension failed the deployment for a generic adapter that injects. One bean with `@Default` beside beans with their own qualifiers is no longer reported ambiguous (BUG-20261117-02, -05, -06, -07, Vidocq/vidocq#652).
* xref:usage.adoc#skip-in-container[`skipObject()` and `skipArray()` work from inside a container] [.tag-new]#NEW# — both JSON-P parsers advance to the end of the enclosing object or array from anywhere inside it; they skipped only when the current event was its `START_OBJECT` or `START_ARRAY` (BUG-20261028-16, Vidocq/champollion#88).
* xref:reference.adoc#boxed-float[A boxed `Float` in a `List`, `Optional` or `Map` compiles] [.tag-new]#NEW# — the generated binding of such a property did not compile (BUG-20261027-03, Vidocq/champollion#87).
* xref:reference.adoc#stable-binding-files[The processor writes the same files at every build] [.tag-new]#NEW# — the services file and `META-INF/champollion/rest-bindings` are sorted by name, so `vidocq dev` no longer restarts the application layer at a save that changed nothing (BUG-20261121-02).
* xref:internals.adoc#protobuf-type-registry[A message type registered for `Any` no longer keeps its application layer] [.tag-new]#NEW# — the Protobuf `TypeRegistry` holds each type weakly: under `vidocq dev`, a discarded layer stayed reachable, and `Any.unpack()` could answer with a class of that layer (BUG-20261117-01).
