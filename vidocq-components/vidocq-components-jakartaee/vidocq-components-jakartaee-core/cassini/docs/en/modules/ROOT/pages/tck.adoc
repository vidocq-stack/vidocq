== Skipped tests by environment (out-of-profile)

The 4.0 TCK categorises tests via JUnit 5 `@Tag`s — `servlet`, `xml_binding`, `security`, `se_bootstrap`. The user-guide §5.2.3 documents excluding them via `excludedGroups` for standalone certifications (Type 1 + Type 3 of TCK Process 1.4.1).

Configuration in `cassini-tck/pom.xml`:

[source,xml]
----
<excludedGroups>servlet,xml_binding</excludedGroups>
----

[cols="1,3,1",options="header"]
|===
| Tag | Justification | Tests removed
| `servlet` | Requires `HttpServletRequest`; out of SE-Bootstrap scope. | ~10
| `xml_binding` | Requires JAXB-runtime; out of Core Profile. | ~120
|===

`security` and `se_bootstrap` are **kept**: Cassini supports BASIC auth (`CassiniSecurityContext`) and native SE-Bootstrap (`ChappeRuntimeDelegate`).

== Intentionally skipped tests (official challenges)

Three test methods across two classes are disabled via `TckChallengeExclusions` (auto-discovered JUnit 5 `ExecutionCondition`) with documented justification — per the **TCK Process 1.4.1**:

[cols="3,1,4",options="header"]
|===
| Test | Category | Reason

| `spec.resource.requestmatching.JAXRSClientIT#locatorNameTooLongAgainTest`
| spec interpretation
| Per a literal reading of §3.7.2 step 2(g), `@GET @Path("locator/locator/locator")` matches `/locator/locator/locator` → 200 expected. The test imposes a non-portable segment-by-segment interpretation.

| `jaxrs31.ee.multipart.MultipartSupportIT#basicTest` + `multiFormParamTest`
| client harness
| Cassini SERVER fully implements §3.5.4 `EntityPart`. The test fails on the Jersey CLIENT side (harness limitation).

|===

Historical note: three additional §11 SSE streaming challenges (`ssebroadcaster#sseBroadcastTest`, `sseeventsink#closeTest`, `sseeventsource#closeTest`) were **lifted with M2i** (2026-06-11) — `ChappeHttpExchange` now opens real chunked streaming (pipe + latch in `ChappeHttpAdapter`, see link:{repo-vidocq}/src/branch/main/vidocq-components/vidocq-components-jakartaee/vidocq-components-jakartaee-core/cassini/ASYNC.md[`ASYNC.md`]), so events reach the wire incrementally and those tests now PASS. `signaturetest.jaxrs.JAXRSSigTestIT#signatureTest` was lifted on 2026-08-27: `run-official-tck-restful-4.0.sh` fetches the EFTL bundle that holds the signature resources, and the test runs and passes.

[#runner-out-of-reactor]
== Runner architecture: in-reactor behind the `tck` profile

`cassini-tck` is an **in-reactor module gated behind the `tck` Maven profile** (TCK harmonisation, same pattern as the `vidocq-runtime-tck-*` runners): a plain `mvn install` neither downloads nor runs anything TCK-related, and the release reactor never sees the module. Invoke through `run-official-tck-restful-4.0.sh`, or directly via `./mvnw -Ptck,tck-official -pl cassini-tck verify`.

Historical note: the module used to be **excluded** from the parent `<modules>` as a standalone Model 4.0.0 POM, because the official Jakarta REST 4.0 TCK transitively pulls **ShrinkWrap Maven Resolver 3.3** (`maven-resolver 1.9` / `maven-model 3.9`), which could not parse the `Model 4.1.0` POMs the workspace used at the time. That constraint disappeared with the workspace-wide migration to Maven 3.9.16 / Model 4.0.0.

== Reproduce locally

[source,bash]
----
# from the root of the monorepo
cd vidocq-components/vidocq-components-jakartaee/vidocq-components-jakartaee-core/cassini

# 1. Prerequisites: Java 25 + Maven 3.10.0 (via .sdkmanrc)
sdk env

# 2. Nothing to install by hand: the build resolves
#    jakarta.ws.rs:jakarta-restful-ws-tck:4.0.1 from Maven Central, and the script
#    downloads the EFTL bundle (signature-test resources, SHA-256 checked) into
#    cassini-tck/target/eftl.

# 3. Run the TCK
./run-official-tck-restful-4.0.sh                          # smoke test
./run-official-tck-restful-4.0.sh all                      # full suite (2670 tests)
./run-official-tck-restful-4.0.sh -Dtest=ResourceTests     # targeted class
----
