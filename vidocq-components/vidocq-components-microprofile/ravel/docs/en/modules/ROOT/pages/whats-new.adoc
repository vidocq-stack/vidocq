= What's new
:description: Everything that changed in this component since the {release-version} release.

[.lead]
New in the `{project-version}` development line — everything listed here landed **after the {release-version} release** and is not part of it. Every entry links to the section that documents it, and those sections carry the [.tag-new]#NEW# badge. Each brick of the suite keeps its own page of this kind; xref:home::whats-new.adoc[the ecosystem index] gathers them. When the next release train ships, this page is frozen with it and restarts empty on the dev line.

* xref:cdi-integration.adoc#start-check[The configuration values are checked by a `Startup` observer] [.tag-new]#NEW# — the build compatible extension reads no configuration any more: it records each required `@ConfigProperty` (key, injected type, `defaultValue`, injection site) and each `@ConfigProperties` class with its prefix, and registers `ConfigStartCheck`, a synthetic observer of `Startup` with priority `0`, which reads `ConfigProvider.getConfig()` and fails the start with one `DeploymentException` listing every problem, worded as before. The check now holds when Vauban runs the extension at build only and loads its result at start; on a full CDI container (Weld, Open Liberty) it runs at `AfterDeploymentValidation` (BUG-20261113-01, Vidocq/ravel#50).
